# Bard v1 명세

이 문서가 **합격 기준**이다. 구현이 여기 적힌 값과 다르면 구현이 틀린 것이다.
로드맵과 의사결정 배경은 [PLAN.md](PLAN.md), 서사 규칙의 근거는 [NARRATIVE.md](NARRATIVE.md),
실패 사례집은 [PIPELINE.md](PIPELINE.md)에 있다.

## 1. 제품

문학 작품의 **세계**를 30~45초 세로 영상으로 만든다. 로컬 GPU 2장으로 전 공정을 돌리고,
사람은 아침에 검수만 한다.

**핵심 원칙: 책 '에 대한' 이야기가 아니라 책 '속' 세계를 그린다.**
출판사·수상 이력·대출 통계를 낭독하면 실패다(v0.9 실측 사고).

### 두 라인

| | 고전 라인 (각색형) | 현대 라인 (소개형) |
|---|---|---|
| 대상 | 저자 사후 70년 경과 | 저작권 존속 |
| 출처 | 위키백과 줄거리·배경 절 | 출판사 소개문 + 위키 첫 문단 |
| 허용 | 줄거리 각색, 장면 재구성 | 배경·공기 묘사 |
| 금지 | 결말 공개 | 줄거리 순서 옮기기, 결말·반전 공개, 본문 인용 |
| 원장 | `works/classics.txt` | 정보나루 인기대출 ∩ KEI 소장 |
| 검증 | `narrative_issues()` | `meta_issues()` |

### 제작 대상 판정

1. **세계 단서**(`world_material`): 고전 4개 이상, 현대 5개 이상.
   장소·계절·사물 단어를 센다. 홍보문뿐인 자료는 여기서 걸린다(실측 1~3개).
2. **저작권**: 고전 원장은 사후 70년 확인 후 등재. 현대서는 각색 금지.
3. **민감 소재 제외**: 실존 참사·실존 인물(5·18, 4·3, 세월호 등)은 무인 제작 금지.
4. **KEI 소장**: 현대서는 소장본만(마무리 문구가 거짓이 되지 않도록).
   고전은 미소장이면 마무리를 "소설 X에서 만날 수 있습니다"로 바꾼다.

## 2. 대본 규격

- **8문장**, 문장당 **26~36자**, 전체 **235~265자**(55초 예산).
  실측 발화 속도는 음성마다 다르다 — 남성 저음 `InJoon` **0.219초/자**, 여성 `SunHi` 0.185.
  기본 음성을 바꾸면 이 예산도 함께 다시 재야 한다.
  마지막 문장은 마무리 문구 길이 + 12자까지 허용.
- 종결어미 계열을 문장별로 배정: 합니다체 · 구어체 · 명사종결 · 합니다체 · 구어체 ·
  명사종결 · 구어체 · 합니다체. 한다체·고어체 금지.
- **목소리**: 기본 `ko-KR-InJoonNeural`(차분한 남성 저음 — 고전 낭독 기준).
  작품별로 `tts_render.py --voice` 로 바꿀 수 있다.
- **톤 6종**: 담담 · 따뜻 · 서늘 · 긴장 · 속삭임 · 생동.
  같은 값 하나가 문장 어휘(`write_script.TONE_RULES`)와 발화 프로소디(`tts_render.TONES`)를 함께 움직인다.
- **강세**: 문장당 한 낱말을 `*별표*`로 감싸면 TTS 가 `<emphasis>` 로 읽는다.
- 마지막 문장은 지정 마무리 문구로 끝나고, 첫 문장의 단어 하나를 되받는다.

### 사실 검증 3중

| 층 | 대상 | 구현 |
|---|---|---|
| 수치 | 자료에 없는 숫자·수량 | `fact_issues()` 정규식 |
| 고유명사·사건 | 지어낸 지명·인물·작품명 | `source_issues()` 모델 대조(판정 전용, 오탐 2중 차단) |
| 출처 | 동음이의 문서 오염 | `wikipedia_summary/plot` 의 저자명 확인 |

수리에 실패하면 원문을 유지하고 `[대조 S3] 재작성 실패 — 아침 검수 대상`을 로그에 남긴다.
**조용히 넘어가지 않는다.**

## 3. 영상 규격

| 항목 | 값 | 근거 |
|---|---|---|
| 해상도 | 1080×1920 (생성 480×848 후 업스케일) | Turing sm_75 VRAM 한계 |
| 프레임 | 24fps | |
| 길이 | **55초 ±5**, 절대 상한 59.9초(쇼츠 60초 경계) | 8문장 × 약 6.9초 |
| 클립 감속 | **1.5배 이하** | 넘으면 화면이 늘어져 보인다. 프레임 수는 4n+1 **올림** |
| 음량 | **−14 LUFS ±2**, 트루피크 −1.0 dBTP 이하 | 유튜브 기준 |
| 자막 | 그림 프롬프트를 **영어로만** 만들어 애초에 글자가 안 생기게 한다 | 프롬프트에 한글이 있으면 모델이 그 글자를 그린다(실측) |
| 크롭 | `crop_keyframe.py` 가 여백을 재서 남은 글자를 잘라낸다 | 고정 비율로는 위치가 제각각인 자막을 못 잡는다 |

## 4. 파이프라인

```
사실파일 → ① 대본(27B + 검증 하네스) → ② TTS(톤·텐션 곡선·강세)
        → ③ 키프레임 8장(Qwen-Image) → ④ 크롭 → I2V 8클립(Wan 2.2)
        → ⑤ 조립(문장별 감속 + loudnorm) → ⑥ 자가점검
```

- 각 단계는 **산출물이 있으면 건너뛴다**(재개 가능). 중간에 죽어도 이어서 진행한다.
- 큐에서 줄을 지우는 시점은 **완성 또는 영구 실패뿐**이다.
- 완료 판정은 종료코드가 아니라 **ffprobe 스트림 확인**으로 한다(거짓 성공 방지).

### 산출물 경로

| 무엇 | 어디 |
|---|---|
| 대본 | `output/<work>/narration_night.json` |
| 음성 | `output/tts/<work>_night_s<N>.wav` |
| 키프레임 | `output/<work>_kf/night_s<N>_*.png` |
| 장면 클립 | `output/<work>_i2v/night_s<N>_00001_.mp4` |
| 완성본 | `output/<work>/final_night.mp4` (실체는 `/data/bard/pipeline`, output 은 심링크) |
| 보기용 발행 | `/data/bard/video/<고전|현대>/<제목>/<제목>_<NN>초_<날짜>.mp4` (하드링크) |
| 자가점검 | `logs/review/<work>.md` |
| 야간 로그·요약 | `logs/night/<날짜>.log`, `logs/night/summary.tsv` |

**자동 공개하지 않는다.** `deliverables/` 승격과 업로드는 사람이 승인한다.
API 는 파일명으로 이를 구분한다 — `final_night*` 는 `kind: "night"`(승인 전),
그 밖의 `final*` 은 `kind: "final"`(승인본). 공개 페이지(`/`)는 **내부 미리보기**로
승인본·야간분 모두 최신 하나씩 보여주되, 승인본만 대표 캐러셀에 올린다.
관리자 페이지는 야간분에 "야간(승인 전)" 라벨을 붙인다. **외부 공개(업로드·deliverables
승격)만 사람 승인 게이트**를 거친다 — 이 페이지는 사설망 전용이다.

## 5. 야간 자동화 시간 정책

**개발 기간(현재): 24시간 무제한 가동.** `DEV_247=1`(기본값)이 모든 시간 게이트를 통과시키고,
정지 타이머는 비활성, 기동 타이머가 매시 15분에 죽은 배치를 되살린다(flock 이 중복 차단).
운영 전환 시 `DEV_247=0` + `aivideo-night-stop.timer` 재활성으로 아래 정책이 살아난다.

| 경계 | 규칙 (운영 전환 후) |
|---|---|
| 20:00 | 기동(`aivideo-night.timer`, 매일) |
| 08:00 (`START_BY`) | **평일**: 이후 새 작품 착수 금지. 이미 착수한 작품은 계속 진행 |
| 09:40 (`FINISH_BY`) | **평일**: 이후 새 장면·새 클립도 시작하지 않음. 진행 중인 클립만 마무리 |
| 09:50 | 최후 안전장치 — **월~금에만** 발동(`Mon..Fri`). 토·일은 정지하지 않는다 |
| **주말** | **금 20:00 → 월 09:40 연속 가동**(토·일은 모든 게이트 통과). 죽으면 토·일 08:30·14:00 재기동 타이머가 되살린다(중복은 flock 차단) |

- 타이머·스크립트 모두 `Asia/Seoul` 명시(서버 시계가 UTC).
- 정지 신호를 받아도 `finish()` 트랩이 생산 요약을 남긴다.
- 개발 중 수동 실행은 `START_BY=1930 FINISH_BY=1930` 처럼 환경변수로 푼다.

## 6. 큐 형식

`works/queue.txt` — TSV 5열:
`작품ID<TAB>사실파일경로<TAB>마무리문구<TAB>화풍블록<TAB>톤`

- 작품ID는 ASCII(파일명·ComfyUI 입력명으로 쓰임). `slug()` 가 한글 제목을 로마자로 옮긴다.
- 4·5열은 비워도 되며 기본 화풍(동판화)과 `담담` 톤이 쓰인다.
- 사실파일의 `[길이] 29-40`, `[톤] 생동` 줄이 큐 값보다 우선한다
  (실행 중인 배치를 수정하지 않고 조정하기 위한 통로).

## 7. 운영 인터페이스

| 경로 | 용도 |
|---|---|
| `/` (3001) | 공개 페이지 — 작품별 최신 완성본 하나, 캐러셀, 인기대출도서 |
| `/admin` (3001) | 관리자 — 대본 편집·재검증, 키프레임, 완성본, **점검 탭** |
| `:8010/api/works` | 작품·버전 목록 |
| `:8010/api/works/{w}/review` | 자가점검 결과(길이·감속·음량·리듬·대본) |
| `:8010/api/books/popular` | 정보나루 인기대출 + KEI 소장 판정 |
| `:8010/api/books/holdings` | KEI 소장 단건 조회(24시간 캐시) |

판정 기준은 **서버가 갖는다.** UI 는 표시만 한다 — 화면과 배치가 다른 말을 하면 안 된다.

## 8. v1 합격 조건

1. 고전 라인이 사실파일 자동 수집 → 완성본까지 사람 손 없이 돈다.
2. 완성본이 길이·감속·음량 세 항목을 모두 통과한다.
3. 대본에 메타 어휘(책·작가·출판사·대출·도서관)가 없다.
4. 자료에 없는 수치·고유명사가 없다(3중 검증 통과, 실패 시 로그에 남음).
5. 야간 자동화가 시간 정책대로 착수·마무리·정지하고 요약을 남긴다.
6. 관리자 페이지에서 점검 결과를 볼 수 있다.
