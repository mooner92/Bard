## 도서 API 시리즈 — "우리 원에 있는 인기도서"

**콘셉트**: 전국 인기대출도서를 API로 받아 → 연구원 도서관 소장 여부를 교차 확인 →
소장된 책만 영상화 → 마무리를 "이 책, 우리 도서관 서가에 있습니다"로. 시청자(원내 구성원)가
"있으니 빌려볼까"로 이어지는 구조.

### 데이터 소스 (접근성 실측 완료)

| 소스 | 역할 | 상태 |
|---|---|---|
| **도서관 정보나루** (data4library.kr) | 인기대출도서 목록 (전국/월별/연령별, ISBN 포함) | HTTP 200 확인. **무료 인증키 필요 — 회원가입 후 발급 (사용자 액션)** |
| **연구원 도서관** (library.kei.re.kr) | 소장 여부 확인 | ✅ **연동 완료.** 화면이 쓰는 Pyxis JSON API가 비로그인 개방(컬렉션 1=소장자료, 10=eBook) — `scripts/kei_holdings.py` + `GET /api/books/holdings` (24h 캐시, 제목·저자 정규화 매칭으로 출판사명 오탐 제거) |
| 알라딘 TTB / 네이버 책 | 표지·소개·평점 메타데이터 보강 | HTTP 200 확인. 키 발급 필요(선택) |
| Wikipedia action API | 고전 라인 사실 수집 | 정책 확인 완료 (UA 필수, maxlag=5, 작품당 1회 캐시) |

### 파이프라인 설계

```
[cron 주1회] 정보나루 인기 100권 (ISBN)
   → KEI 소장 교차 확인 (ISBN 매칭)
   → 신규 교집합만 works 큐에 등록 (SQLite: isbn, title, author, holdings_callno, status)
   → 관리자 페이지 승인 게이트
   → 대본 하네스 (현대서 전용 포맷) → 키프레임 → I2V → 조립
   → 마무리: "이 책은 도서관 [청구기호]에 있습니다"
```

### ⚠️ 현대서는 각색 금지 — 포맷이 다르다

고전 라인(각색·줄거리 재구성)은 퍼블릭 도메인이라 가능했지만, **현대 저작물의 줄거리
각색·재연은 2차적 저작물 침해 소지**가 있고 유튜브 "본인이 만들지 않은 자료" 정책에도 닿는다.
현대서 포맷은 **"이 책이 답하는 질문 3가지"** 소개형으로 간다:
훅(책이 던지는 도발적 질문) → 질문 3개를 정보격차형으로 → "답은 서가에" 마무리.
표지·본문 낭독을 화면에 쓰지 않는 우리 파이프라인(생성 이미지)이 여기서 강점이 된다.
짧은 인용(1문장 이내)은 인용권 범위에서 유지.

### 사용자 액션 필요

1. **정보나루 인증키**: data4library.kr 회원가입 → 인증키 신청 (무료, 즉시~1일)
2. ~~KEI 도서관 API URL~~ ✅ 해결 — 번들 분석으로 Pyxis API 직접 확인, Playwright 불필요.
   실측: `GET /pyxis-api/1/collections/{1|10}/search?all=k|a|검색어`. 인기대출 톱10 중 7권 KEI 소장 확인.
3. (선택) 알라딘 TTB 키

- A/B 1회는 파일 수동 업로드로 충분 — UI를 기다릴 이유가 없음

**v1 범위 (예상 1~2일):**

| 화면 | 기능 |
|---|---|
| 작업 큐 | jobs 목록·상태·진행률 (backend/db.py 이미 존재) |
| 대본 검수 | 문장별 표시 + 검증 결과 배지 + **인라인 수정** + 승인/재생성 |
| 키프레임 갤러리 | 장면별 이미지 + 승인/재생성(시드 변경)/참조 편집 요청 |
| 완성본 | 플레이어 + 다운로드 + 업로드 큐 등록 |
| 작품 관리 | works CRUD (제목·사실·스타일 블록·어미 플랜) + 도서 API 유입분 승인 |

**스택**: Next.js(:3001, Node 20 설치 완료) + FastAPI(:8000) + 기존 SQLite.
UI·cron·에이전트가 **같은 REST API**를 쓰는 것이 설계 원칙 (n8n식 동작의 본질).
systemd 유닛 2개 추가로 재부팅 영속화.

## 관리자/공개 페이지 분리 — 미착수 명세 (2026-08-13 요청)

현재 `/`가 관리자 화면이다. 아래대로 재구성한다.

### 라우팅
- `/` — **공개 페이지**. 방문자용. 상단 메뉴로 `영상` · `인기대출도서` 전환(토스식 상단 네비, 현행 스타일 유지)
- `/admin` — 현행 관리자 화면을 그대로 이동

### 공개 페이지
- 작품당 **최신 완성본 하나만** 노출 (`kind==="final"` 이면서 `compressed` 제외, `updated` 최신)
- 상단 **캐러셀** — 5초 자동 회전, 재생 중에는 정지, 점 인디케이터로 수동 이동
- 카드 클릭 시 **모달 팝업 재생** — 배경 딤, ESC/바깥 클릭 닫기, `playsInline`·`preload="metadata"`로 부드럽게
- 인기대출도서는 하단 나열이 아니라 **별도 탭**

### 관리자 페이지 (`/admin`)
- 완성본 탭에서 **종류·버전 구분** — 백엔드가 `kind`(`final`/`scene`/`other`)와 `version`(`v3.2` 등)을 이미 내려준다.
  현재 카프카가 9개를 구분 없이 보여주는 문제가 이것으로 해소된다. 장면 클립은 접어두고 완성본만 기본 노출
- 버전 목록에 **최종 수정 타임스탬프** 표기 — `/api/works`의 `updated`(ISO 8601 UTC) 사용
- 45초 최종본만 예외적으로 버전 표기 없이 대표로 노출

### 백엔드 (완료됨)
- `GET /api/works` → `updated` 추가
- `GET /api/works/{work}/videos` → `kind`·`version`·`updated` 추가, 완성본 우선 정렬

## 야간 상시 제작 (강제 명세) — 20:00 ~ 익일 08:00

**GPU는 근무시간 외에 반드시 일하고 있어야 한다.** 하루 12시간 × 클립 7.3분이면
이론상 **약 98클립 = 완성본 12편**이다. 이 창을 비우는 것은 자원 낭비로 간주한다.

### 규칙
1. **20:00 기동.** `keiwi` 스타일 systemd 타이머 2종(`aivideo-night.timer` 기동,
   `aivideo-night-stop.timer` 강제 정지)으로 강제한다. cron이 아니라 systemd인 이유는
   재부팅 후 자동 복구와 `journalctl` 로그가 표준으로 붙기 때문이다.
   타이머·스크립트 모두 `Asia/Seoul` 을 명시한다 — 서버 시계가 UTC라 지정하지 않으면
   20:00 이 한국시간 새벽 5시가 된다(실측 사고).
2. **작업 단위는 작품 1편**이며, 큐가 비면 즉시 종료한다(빈 루프 금지).
3. **착수 시각과 마무리 시각을 분리한다.**
   - `START_BY=08:00` — 이후에는 **새 작품을 시작하지 않는다**.
   - **이미 착수한 작품(대본이 있는 작품)은 08:00 을 넘겨도 끝까지 마친다.** 중간에 끊으면
     그때까지 만든 키프레임·클립이 놀고, 다음 밤에 같은 자리를 다시 밟는다.
   - `FINISH_BY=09:40` — 다른 이용자가 10시쯤 서버를 쓰기 시작하므로, 이후에는
     새 장면·새 클립도 시작하지 않고 진행 중인 클립만 끝낸다.
   - `aivideo-night-stop.timer` 09:50 은 최후의 안전장치다(`SIGTERM` 후 유예 900초).
     정상적으로는 스크립트가 스스로 먼저 끝난다. 두 값은 환경변수로 덮어쓸 수 있어
     개발 중 수동 실행에는 `START_BY=1930 FINISH_BY=1930` 처럼 풀어 쓴다.
4. **정지 신호를 받아도 생산 요약을 남긴다.** `SIGTERM` 트랩으로 종료 사유·완성 편수를
   `logs/night/summary.tsv` 에 기록한다. 트랩이 없으면 강제 종료된 밤은 기록이 통째로 빈다.
4. **실패한 작품은 건너뛰고 다음으로 간다.** 한 작품의 실패가 밤 전체를 멈추면 안 된다.
5. **산출물은 자동 공개하지 않는다.** 야간 배치는 `output/`까지만 만들고,
   `deliverables/` 승격과 업로드는 사람이 관리자 페이지에서 승인한다(§검수 게이트).
6. **로그는 `logs/night/<날짜>.log`에 남긴다.** 아침에 무엇이 돌았는지 한 파일로 확인된다.

### 큐 정의
`works/queue.txt` — 한 줄에 작품 하나. 탭 5칸:
`작품ID<TAB>사실파일경로<TAB>마무리문구<TAB>화풍블록<TAB>톤`.
4·5칸은 비워도 되며 각각 기본 화풍(동판화)과 `담담` 톤이 쓰인다.
톤은 `scripts/tts_render.py` 의 6종(담담·따뜻·서늘·긴장·속삭임·생동)이고,
사실파일에 `[톤] 생동` 줄이 있으면 그쪽이 우선한다(문장 어휘와 발화가 같은 값으로 움직인다).
작품ID는 파일명·ComfyUI 입력명이 되므로 ASCII 여야 한다 —
`scripts/fetch_book_facts.py` 의 `slug()` 가 한글 제목을 로마자로 옮긴다.
처리한 줄은 `works/done.txt`로 옮긴다. 파일 기반인 이유는 워커 미구현 상태에서도
즉시 동작하고, 나중에 SQLite 큐(`backend/db.py`)로 옮길 때 인터페이스가 같기 때문이다.

### 확인
```bash
systemctl list-timers 'aivideo-night*'        # 다음 기동 시각
journalctl -u aivideo-night -n 50             # 지난밤 실행 기록
tail -f logs/night/$(date +%F).log            # 진행 중 확인
```
